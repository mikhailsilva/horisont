# ITles: работа в репозитории

## Что считать результатом

- Продукт: удалённый мониторинг спецтехники для FUCHS, дистрибьюторов и владельцев. Базовое ТЗ — моточасы, пробег и местоположение; масло добавлено позже. Начните с `README.md`, `docs/design/DESIGN-v2.md` и `docs/ROADMAP.md`.
- Различайте **запущенный код**, **данные имитатора, переданные настоящим протоколом**, **пакеты реальных трекеров из тестовых наборов** и **проверку на смонтированной машине**. Последняя пока не подтверждена. Числа из моделирования нельзя называть результатом полевого испытания; для инженерных заявлений указывайте источник и метод проверки.
- Сначала использовать существующий трекер/API, телефон или показание счётчика; монтаж и покупку оборудования предлагать только после проверки доступных каналов. Координаты отключает администратор владельца; не добавляйте сбор персональных данных без отдельного решения.

## Инструменты и сотрудничество

- **Перед любой задачей с MCP** прочитайте `.agents/skills/mcp-servers/SKILL.md`. Имена/номера серверов меняются между запусками: сначала обнаружьте доступные инструменты, затем вызывайте нужные. Для Vercel, Cloudflare, научных источников, Context7 и 21st.dev используйте соответствующий доступный MCP, а не предположения по старой переписке.
- Делегируйте субагентам независимые ограниченные исследования, тесты или ревью, когда это ускоряет задачу. Давайте чёткие границы; каждый читает применимые `AGENTS.md`. Не допускайте конкурирующих правок одних файлов. Основной агент перепроверяет результаты и отвечает за итог.
- Конфиденциальное: архивы прежних чатов содержат строки подключения и другие закрытые сведения. **Не коммитьте сырые транскрипты, выгрузки MCP, значения переменных окружения, скриншоты с данными клиентов и локальную `.hoplite/`**. В документации — только обезличенные выводы и имена необходимых переменных; при обнаружении утечки предложите ротацию.
- Перед публикацией проверьте `git remote -v`, привязку учётных данных и базу PR. Текущий репозиторий владельца — `mikhailsilva/horisont`; `raulwulff6769/framework-lab` — источник переноса, а не адрес новых PR. Не обновляйте ветку по умолчанию напрямую. Продакшен и внешние ресурсы не меняйте в рамках исследования без явного согласования.

## Субагенты

При каждом `subagent_control` с `op: "spawn"` **обязательно** указывать `model`. Разрешены только проверенные route:

- `openai/gpt-6-luna`
- `z-ai/glm-5.3-flash`

Не использовать модель делегирования по умолчанию или третью модель. Если один route отклонён, можно попробовать только второй; если не работает и он — сообщить об ошибке, не запускать субагента с пропущенным `model`. Эти правила действуют для всех субагентов, запускаемых при работе в этом репозитории.

`max` — уровень reasoning, а не часть ID модели. Интерфейс `subagent_control` не принимает настройку effort: не утверждать, что `max` был установлен, если это не подтверждено вызовом или runtime. При задаче, где критичен максимальный effort, предпочесть `z-ai/glm-5.3-flash` (его документация указывает `max` по умолчанию); использовать `openai/gpt-6-luna` с требованием `max` только при наличии явной настройки effort.

## MCP

При задаче, где могут пригодиться MCP-инструменты, прочитать `.agents/skills/mcp-servers/SKILL.md`. Наличие серверов и имён инструментов проверять через доступные в текущем сеансе `mcp_server_N_list_tools` перед вызовом `mcp_server_N_call`; карта в скилле — ориентир, а не гарантия неизменности API.

## Проверка изменений

- Python: `.venv/bin/python -m pytest -q tests`; платформа: `pnpm --dir platform typecheck`, `pnpm --dir platform test`, `pnpm --dir platform build:vercel`.
- Сквозной сценарий `scripts/gateway_e2e.py` проверяет TCP → очередь шлюза → API на **моделируемом** парке. При изменении протокола, расчётов или API добавляйте тесты с атрибутированными пакетами и перепроверяйте соответствующий сценарий. При изменении UI проверяйте его в работающем приложении.
- Состояние релиза, Vercel и планы — `docs/ROADMAP.md`; методы развёртывания и безопасной проверки — `docs/operations/vercel.md`. Датированные наблюдения обновляйте, а не выдавайте за вечные свойства сервиса.
